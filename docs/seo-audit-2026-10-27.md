# CardIQ SEO audit — 27 October 2026

Status: fixes implemented locally; not deployed by this audit.

## Scope and evidence

Read-only production checks covered the homepage, journal, INFINIA page, robots.txt, sitemap.xml and a nonexistent URL. Production returns HTTP 200 for expected pages, a genuine HTTP 404 for the nonexistent URL, self-referencing HTTPS canonicals and a crawlable robots file declaring the sitemap. The sitemap contains 431 URLs. These checks do not establish Google indexing or rankings.

The updated production build was created in a new temporary directory. All 431 sitemap targets were then audited locally for file existence, one matching canonical, a unique title and description, one H1, parseable JSON-LD and resolving internal HTML links. Result: zero detected errors. Twenty-five static-site regression tests and the optimized frontend build pass.

## Changes made

- Replaced the vague homepage title with “Compare Credit Cards in India: Fees & Rewards | CardIQ”. Added WebSite and Organization structured data plus crawlable no-JavaScript links to the catalogue, comparison hub, guides, calculator and methodology.
- Changed card-page structured data from generic Product to CreditCard, with an issuer provider, India service area and documented fee/condition information. No rating, offer or approval claims were invented. CreditCard schema does not guarantee a Google rich-result feature.
- Added consistent author identity, publisher and mainEntityOfPage to all guide Article nodes, including articles using an @graph. Open Graph page type now follows the actual schema nodes.
- Shortened repetitive card and comparison title suffixes while preserving product names and unique guide titles. Long-title advisories decreased from 156 to eight. The remaining eight preserve full product names; the 70-character audit threshold is a heuristic, not a Google limit.
- Corrected the comparison hub’s application link to open comparison mode.
- Added scripts/audit_seo.py and a deployment-workflow audit step so broken sitemap targets, duplicate metadata, invalid JSON-LD and internal-link regressions fail verification.
- Added a configurable generation output folder and a preserve-generated-files option. This audit used a new temporary folder and skipped route cleanup. Existing site files and operations documents were preserved.

## Remaining work and limits

- Google Search Console access is needed to inspect indexing coverage, Google-selected canonicals, search queries, impressions and clicks. Submit/inspect the existing sitemap there; no submission was performed.
- Field Core Web Vitals, Lighthouse and mobile performance were not measured. Do not infer a performance score from metadata or build size.
- Only representative endpoints were requested from production; all 431 URLs were checked in the local generated output, not individually fetched from the live host.
- The catalogue-driven comparisons and short general guides still warrant editorial review for distinct, useful decision guidance. Do not expand page counts merely to target more keywords.
- Publication dates were not manufactured from issuer-verification dates. Article dates and sitemap lastmod should be introduced only with a maintained record of meaningful page updates.
